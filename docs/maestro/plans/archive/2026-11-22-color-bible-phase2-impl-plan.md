## Phase 1: Database, Migrations & Repository

### Objective
Implement the persistent SQLite database, foreign key management, versioned idempotent schema migrations, and the repository layer (`ColorBibleRepository`).

### Agent: `coder`
### Parallel: No

### Files to Create
- `ai_remaster_gui/color_bible_db.py` — Database schema creation, `schema_migrations`, `ColorBibleRepository` interface and SQLite implementation, connection management with WAL mode and `PRAGMA foreign_keys = ON`, database path resolution (`resolve_color_bible_db`).

### Implementation Details
- Tables: `schema_migrations`, `films`, `sequences`, `shots`, `characters`, `appearance_variants`, `objects`, `locations`, `shot_entity_assignments` (nullable `shot_id`), `color_references` (with `approval_status`).
- Connection factory supporting `:memory:`, explicit paths, and environment variable `ARP_COLOR_BIBLE_DB`.
- Transaction safety with rollback on failure and automatic index creation.

### Validation
- Unit test initializing an in-memory and disk database multiple times, verifying idempotency and schema integrity.

### Dependencies
- Blocked by: None
- Blocks: Phase 2

## Phase 2: Color Science & Service Layer

### Objective
Implement the vectorized NumPy color extraction algorithms (sRGB to CIE-LAB, percentiles, deterministic RGB palette), shot manifest synchronization, disjoint shot range resolution, and canonical deterministic snapshot hashing.

### Agent: `coder`
### Parallel: No

### Files to Create
- `ai_remaster_gui/color_science.py` — Vectorized color transformations (sRGB &harr; CIE XYZ &harr; CIE-LAB under D65 standard illuminant), percentile calculation (`p10, p25, p50, p75, p90`), deterministic dominant RGB palette quantization, and binary mask slicing.
- `ai_remaster_gui/color_bible_service.py` — `ColorBibleService` business logic orchestrating `ColorBibleRepository`, manifest CSV parsing/syncing, non-contiguous range assignment resolution, and canonical SHA-256 snapshot hashing.

### Implementation Details
- Fast vectorized math using NumPy array broadcasting for full images or masked subsets.
- Snapshot hash generated by serializing all approved references (`approval_status = 'approved'`) and assignments in sorted canonical order, formatted as `sha256:<hex>`.

### Validation
- Synthetic image & mask color extraction tests against ground truth D65 values.
- Multi-range assignment queries (e.g. shots 12–18 and 410–435) returning exact assigned variants.

### Dependencies
- Blocked by: Phase 1
- Blocks: Phase 3

## Phase 4: Server API & Frontend Workbench Tab

### Objective
Expose secure REST endpoints under `/api/color-bible/*` and implement the `Color Bible` workbench tab in the browser GUI.

### Agent: `coder`
### Parallel: No

### Files to Create
- `ai_remaster_gui/static/js/render-color-bible.js` — Client-side rendering script for the split workbench: entity/variant tree and shot range controls on the left, reference stills, RGB palettes, LAB percentiles, and approval buttons on the right.

### Files to Modify
- `ai_remaster_gui/http_handler.py` — Add `/api/color-bible/*` routes (`state`, `sync-manifest`, `entity`, `variant`, `assign-range`, `reference`, `reference-approval`, `snapshot-hash`) with host/origin verification and `resolve_served` path validation.
- `ai_remaster_gui/server.py` — Extend `state()` to provide Color Bible context when `view == 'color_bible'`.
- `ai_remaster_gui/static/js/core.js` — Register `color_bible` in `availableTabs()` and `drawTabs()`.
- `ai_remaster_gui/static/js/app.js` — Dispatch to `drawColorBible()`.
- `ai_remaster_gui/static/index.html` — Include `render-color-bible.js`.
- `ai_remaster_gui/static/styles.css` — Styling for the split workbench, palette swatches, and range chips.

### Implementation Details
- Strictly enforce `resolve_served()` on any file path passed from the client.
- Responsive CSS layout with dark theme consistent with ARP.

### Validation
- HTTP route security tests confirming 403 on invalid origins and proper 200 responses on valid local calls.

- Blocked by: Phase 3
- Blocks: Phase 5
